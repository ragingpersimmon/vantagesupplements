# Phase 1: Backend boots, inputs distributed
**Model:** Sonnet 5.5 / Medium. **Branch:** `phase-1-boot`

## Read
`launch.env`, `backend/{Dockerfile,docker-compose.yml,.env.example}`, `backend/config/initializers/vantage.rb`,
`storefront/.env.example`, `scripts/.env.example`, `README.md` § Local development.

## Do
1. If `launch.env` is missing, copy `launch.env.example` to it and continue with the fallbacks.
2. Create `backend/.env`, `storefront/.env.local` and `scripts/.env` from their examples. Generate every
   secret with `openssl rand`. Copy the matching values from `launch.env` (GOOGLE_CLIENT_ID goes to the backend and
   to NEXT_PUBLIC_GOOGLE_CLIENT_ID; SHIP_FROM_PROVINCE goes to scripts). Write `scripts/sync-env.ts` so this is re-runnable
   (`pnpm sync-env` from scripts/), never overwriting existing secrets.
3. `cd backend && docker compose up -d --build --wait`, then `docker compose exec web bin/rails db:seed`.
4. Create the 3 API keys (README § 2), and write them into storefront/.env.local and scripts/.env.
5. Use the Admin API (a `scripts/setup-store.ts`, idempotent): store currency CAD, default country CA,
   market "Canada" (CAD, en+fr), and one stock location "Main warehouse" in SHIP_FROM_PROVINCE.
6. Add `.claude/` permission fixes if any routine command was blocked.

## Accept
- `curl -sf localhost:4000/up` → 200. The `worker` container is healthy.
- A Store API login with `{"provider":"google","id_token":"junk"}` returns "Invalid Google credential"
  (proves the provider is registered), not "unknown provider".
- Re-running sync-env and setup-store changes nothing.
